## 二、后端模块划分（Maven 多模块）

依赖关系是单向的，从下往上：

```
ai-collab-admin（启动模块）
  ├── ai-collab-security
  ├── ai-collab-sys
  ├── ai-collab-blog
  └── ai-collab-notice
        ├── ai-collab-integration
        └── ai-collab-common
```

### ai-collab-common（通用模块）

谁都能用，不依赖任何业务模块。

| 内容 | 说明 |
|---|---|
| `models/Result.java` | 统一返回结构，所有接口都返回这个壳 |
| `models/PageResult.java` | 分页返回结构 |
| `models/po/BasePo.java` | 实体基类，含创建时间/更新时间/逻辑删除 |
| `models/enums/AuditStatusEnum.java` | 审核状态枚举 |
| `constance/CommonConst.java` | 全局常量（角色ID、状态码、消息类型） |
| `constance/FileConst.java` | 文件上传常量（大小限制、格式白名单） |
| `constance/redis/RedisKeyConst.java` | Redis key 命名规范 |
| `exception/BusinessException.java` | 业务异常 |

### ai-collab-integration（集成模块）

跟第三方或系统层打交道的东西。

| 内容 | 说明 |
|---|---|
| `security/SecurityContext.java` | 登录用户上下文（ThreadLocal） |
| `utils/FileUploadUtils.java` | 文件上传：存盘、生成唯一名、按日期分目录 |
| `utils/FileDownloadUtils.java` | 文件下载 |
| `utils/FileTypeValidatorUtils.java` | 文件类型白名单校验 |
| `models/enums/FileTypeEnum.java` | 允许的文件类型 |
| `validation/FileType.java` | 自定义文件类型校验注解 |
| `handler/FileUploadHandler.java` | 上传处理 |

### ai-collab-security（安全模块）

| 内容 | 说明 |
|---|---|
| `security/JwtUtil.java` | JWT 签发与解析（密钥从配置读，不写死） |
| `security/AuthInterceptor.java` | 登录拦截器，校验 token + Redis 登录态 |
| `security/WebSecurityConfig.java` | 拦截器注册 + 免登录白名单 |
| `security/IgnoreAuth.java` | 免登录注解 |
| `security/PasswordConfig.java` | BCrypt 密码加密器 |

**登录流程**：
```
用户提交账号密码
  → Service 查库校验（BCrypt 比密码）
  → 校验 audit_status=1（已审核）和 enable=1（未禁用）
  → JwtUtil 签发 token，同时往 Redis 写登录态
  → 返回 token + 用户信息给前端
  → 前端存 localStorage，后续请求带 Authorization: Bearer <token>
```

**鉴权流程**：
```
请求进来
  → AuthInterceptor 拦截
  → 有 @IgnoreAuth 直接放行
  → 取请求头 token，JwtUtil 验签
  → 查 Redis 登录态是否还在（管理员能踢人）
  → 塞进 SecurityContext（供业务层取当前用户）
  → 请求结束 clear()，防止线程复用串号
```

### ai-collab-sys（系统模块）

用户、角色、邮件、用户审核、找回密码。

### ai-collab-blog（业务模块）

平台的核心：内容发布、对接申请、内容审核、收藏。

| 内容 | 说明 |
|---|---|
| `service/IBlogArticleService.java` | 文章/内容：发布、查询、审核、批量审核 |
| `service/IBlogRegistrationService.java` | 对接申请：提交、处理、进度更新 |
| `service/IBlogDictService.java` | 字典：类型、状态、进度、标签 |
| `service/IUserFavoriteService.java` | 收藏/关注 |

### ai-collab-notice（通知模块）

| 内容 | 说明 |
|---|---|
| `service/INoticeService.java` | 站内消息：发送、查询、已读 |
| `service/IChatService.java` | 站内会话（新增功能） |

### ai-collab-admin（启动模块）

Controller 层 + 配置 + 启动类。**只有这一层跟 HTTP 打交道。**

## 四、请求链路示例

以「学生对别人的内容表达兴趣」为例：

```
1. 前端 BrowseProjects.vue
   用户点「申请对接」→ 填表单 → submitRegistration()

2. src/api/blog.js
   POST /api/blog/registration
   请求头带 Authorization: Bearer <token>

3. Nginx
   /api/ 前缀去掉，转发到 http://后端:28848/blog/registration

4. AuthInterceptor
   验 token → 查 Redis → SecurityContext.setUserId(当前用户)

5. BlogRegistrationController
   接收 RegistrationSubmitDTO，@Valid 校验参数
   调 IBlogRegistrationService.submitRegistration(dto, SecurityContext.getUserId())

6. BlogRegistrationServiceImpl
   - 校验：不能申请自己的内容
   - 校验：不能对自己填写的内容表达兴趣
   - 落库 blog_registration
   - 调 INoticeService.sendNotice() 通知文章发布者

7. 返回 Result.success(申请ID)
   前端收到 → 弹提示 → 刷新列表
```

## 五、几条设计约定

### 统一返回结构

所有接口都返回：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": { ... }
}
```

- `code=200` 成功
- `code=400` 参数错误
- `code=401` 未登录/登录失效（前端自动跳登录页）
- `code=403` 没权限
- `code=500` 业务失败或服务器异常

### 分页参数

统一用 `pageNumber`（从 1 开始）+ `pageSize`，返回：
```json
{
  "records": [],
  "total": 100,
  "pageNumber": 1,
  "pageSize": 10,
  "pages": 10
}
```

### 逻辑删除

表里有 `delete_time` 字段，删除是打时间戳不是物理删。
实体类上标 `@TableLogic`，MyBatis-Plus 自动处理，查询会自动过滤已删除数据。

### 公共字段自动填充

`create_time` / `update_time` / `create_by` / `update_by` 由
`MyMetaObjectHandler` 自动填充，Service 里不用手动 set。

### 文件访问路径

上传的文件存在 `WebFile/` 目录，数据库里存相对地址。
前端通过 `/WebFile/xxx` 访问，Nginx 配静态映射。
