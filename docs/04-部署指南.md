# 部署指南

## 一、环境要求

| 软件 | 版本 | 说明 |
|---|---|---|
| JDK | 17+ | 后端运行环境 |
| Maven | 3.8+ | 后端打包 |
| MySQL | 8.0+ | 数据库 |
| Redis | 7.0+ | 缓存（登录态） |

## 二、本地开发跑起来

### 2.1 准备数据库

```bash
mysql -uroot -p < ai-collab-hub-server/sql/ai_collab_hub.sql
```

会建库 `ai_collab_hub` + 全部表 + 初始数据。

### 2.2 起 Redis

```bash
redis-server
```

### 2.3 改后端配置

编辑 `ai-collab-hub-server/ai-collab-admin/src/main/resources/application.yaml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/ai_collab_hub?...
    username: root
    password: "你的密码"          # ← 改这里

  data:
    redis:
      host: 127.0.0.1
      port: 6379
      database: 1                 # ← 注意是 1 号库
      password: ""                # ← 有密码就填

ai-collab:
  jwt:
    secret: "换成你自己的密钥，至少32位"   # ← 上线前必改
```

```bash
cd ai-collab-hub-server
mvn clean package -DskipTests
java -jar ai-collab-admin/target/AiCollabHub.jar
```

启动后访问 http://localhost:28848/doc.html 看接口文档。
看到控制台打印「人工智能学院双创平台 启动完成」就是好了。

### 2.5 起前端

```bash

npm install
npm run dev
```

访问 http://localhost:3000

**默认管理员账号：admin / `ChangeMe@123`**（首次部署后请立刻修改）

## 三、Linux 服务器部署

以 `/srv/ai-collab-hub` 为部署根目录为例。

### 3.1 目录规划

```
/srv/ai-collab-hub/
├── server/                    # 后端
│   ├── AiCollabHub.jar
│   ├── application-prov.yaml  # 生产配置
│   ├── logs/                  # 日志
│   └── WebFile/               # 用户上传文件
├── web/                       # 前端构建产物
│   └── （dist 里的文件）
└── nginx/
    └── conf.d/ai-collab.conf
```

### 3.2 后端打包与部署

在开发机（或服务器上装了 Maven 的话直接在服务器）：

```bash
cd ai-collab-hub-server
mvn clean package -DskipTests
```

产物：`ai-collab-admin/target/AiCollabHub.jar`

传到服务器：

```bash
scp ai-collab-admin/target/AiCollabHub.jar root@服务器IP:/srv/ai-collab-hub/server/
```

在服务器上创建生产配置 `/srv/ai-collab-hub/server/application-prov.yaml`：

```yaml
server:
  port: 28848

spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://127.0.0.1:3306/ai_collab_hub?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false
    username: root
    password: "生产库密码"
  data:
    redis:
      host: 127.0.0.1
      port: 6379
      database: 1
      password: "生产 Redis 密码"

ai-collab:
  jwt:
    secret: "生产环境专用的长密钥，至少32位，别用默认值"
    expire: 604800000
  upload:
    root-dir: "/srv/ai-collab-hub/server/WebFile"
    visit-prefix: "/WebFile"

logging:
  file:
    name: /srv/ai-collab-hub/server/logs/AiCollabHub.log
```

启动：

```bash
cd /srv/ai-collab-hub/server
nohup java -jar AiCollabHub.jar --spring.profiles.active=prov > /dev/null 2>&1 &
```

### 3.3 前端构建与部署

```bash
cd ai-collab-hub-web
npm install
npm run build
```

产物在 `dist/`。传到服务器：

```bash
scp -r dist/* root@服务器IP:/srv/ai-collab-hub/web/
```

### 3.4 Nginx 配置

`/etc/nginx/conf.d/ai-collab.conf`：

```nginx
server {
    listen 80;
    server_name 你的域名;
    # HTTP 跳 HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name 你的域名;

    ssl_certificate     /srv/ai-collab-hub/nginx/ssl/fullchain.pem;
    ssl_certificate_key /srv/ai-collab-hub/nginx/ssl/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    # 前端静态文件
    root /srv/ai-collab-hub/web;
    index index.html;

    # 支持前端 history 路由（刷新不 404）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 接口反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:28848/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 上传大文件要放开
        client_max_body_size 1024M;
        proxy_read_timeout 300s;

        # 跨域预检
        if ($request_method = OPTIONS) {
            add_header Access-Control-Allow-Origin *;
            add_header Access-Control-Allow-Methods 'GET, POST, PUT, DELETE, OPTIONS';
            add_header Access-Control-Allow-Headers 'Authorization, Content-Type';
            return 204;
        }
    }

    # 用户上传的文件
    location /WebFile/ {
        alias /srv/ai-collab-hub/server/WebFile/;
        expires 30d;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|svg|woff2?|ttf)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    access_log /var/log/nginx/ai-collab-access.log;
    error_log  /var/log/nginx/ai-collab-error.log;
}
```

检查并重载：

```bash
nginx -t
nginx -s reload
```

## 四、Docker 部署（可选）

### 4.1 后端 Dockerfile

放在 `ai-collab-hub-server/` 下：

```dockerfile
FROM openjdk:17-jdk-slim
WORKDIR /app
COPY ai-collab-admin/target/AiCollabHub.jar app.jar
EXPOSE 28848
ENTRYPOINT ["java", "-jar", "app.jar", "--spring.profiles.active=prov"]
```

构建：

```bash
cd ai-collab-hub-server
mvn clean package -DskipTests
docker build -t ai-collab-hub:1.0.0 .
docker run -d --name ai-collab-hub \
  -p 28848:28848 \
  -v /srv/ai-collab-hub/server/logs:/app/logs \
  -v /srv/ai-collab-hub/server/WebFile:/app/WebFile \
  -v /srv/ai-collab-hub/server/application-prov.yaml:/app/application-prov.yaml \
  ai-collab-hub:1.0.0
```

### 4.2 前端 Dockerfile

放在 `ai-collab-hub-web/` 下：

```dockerfile
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

FROM nginx:1.25-alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

### 4.3 docker-compose

```yaml
version: '3.8'
services:
  ai-collab-hub:
    image: ai-collab-hub:1.0.0
    container_name: ai-collab-hub
    ports:
      - "28848:28848"
    volumes:
      - ./server/logs:/app/logs
      - ./server/WebFile:/app/WebFile
      - ./server/application-prov.yaml:/app/application-prov.yaml
    restart: always

  ai-collab-web:
    image: ai-collab-web:1.0.0
    container_name: ai-collab-web
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/ssl:/etc/nginx/ssl
    depends_on:
      - ai-collab-hub
    restart: always
```

启动：

```bash
docker compose up -d
```

## 六、常见问题

### 后端启动报数据库连接失败

- 检查 MySQL 是否启动、账号密码是否正确
- 检查库名是不是 `ai_collab_hub`
- 检查 `allowPublicKeyRetrieval=true&useSSL=false` 有没有带（MySQL 8 需要）

### 登录后立刻掉线

- 检查 Redis 是否启动
- 检查 `database: 1` 配置
- Redis 有密码的话必须配 `password`

### 前端能打开但接口全 404

- 检查 Nginx 的 `/api/` 反代配置
- 后端端口是不是 28848
- `proxy_pass` 末尾的 `/` 不能少（少了会把 /api 带过去）

### 上传文件失败

- 检查 `client_max_body_size` 有没有放开
- 检查 `WebFile` 目录权限
- 单文件不能超过 100MB，总数不能超过 1024MB

### 刷新页面 404

- Nginx 少了 `try_files $uri $uri/ /index.html;`

### 中文乱码

- 数据库建库时用 `utf8mb4`
- JDBC url 带 `characterEncoding=utf8`
- 检查服务器 locale

## 八、前端免费上线：GitHub Pages

> 想让别人**直接打开网址看界面**，又不想马上买服务器 —— 用 GitHub Pages 托管前端。
> 注意：**只能放前端**，后端依然要单独部署（见第九节）。

### 8.1 三个硬限制（先知道，少走弯路）

**① 私有仓库用不了免费 Pages**

GitHub 会提示「升级或将此仓库公开以启用页面」。
免费版只有**公开仓库**能用 Pages。

**② Pages 跑不了后端**

它只托管静态文件，Java 服务 / MySQL / Redis 全跑不了。
部署完必然是「前端能打开、接口全部失败」—— 这是**预期状态**，不是 bug。

**③ 别选错「来源」**

设置页的来源有两类：

| 选项 | 说明 |
| --- | --- |
| Deploy from a branch | 从分支读静态文件（**推荐，最稳**） |
| GitHub Actions | 走 workflow 构建（YAML 写错就 404） |
| ~~Jekyll / Static HTML~~ | 建站模板，**选了不会跑我们的 workflow** |

### 8.2 前端要改的四处

**① 路由改 hash 模式**

`createWebHashHistory` —— 静态托管没有服务端路由回退，`history` 模式**刷新页面会 404**。

```js
// src/router/index.js
import { createRouter, createWebHashHistory } from 'vue-router'
const router = createRouter({
  history: createWebHashHistory(),
  routes
})
```

**② vite 的 base 指向仓库子路径**

Pages 地址是 `https://用户名.github.io/仓库名/`，**不是根路径**。
不改的话所有 js/css 都 404（页面白屏）。

```bash
# ai-collab-hub-web/.env.production
VITE_BASE=/ai-collab-hub/
VITE_API_BASE=/api     # 见第③点，有后端公网地址后要改
```

**③ API 地址改成环境变量**

本地开发走 Vite proxy（`/api` → localhost:28848），
但静态托管**没有代理服务**，必须直连后端绝对地址。

```js
// src/api/request.js
const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE || '/api',   // 本地兜底 /api
  timeout: 30000
})
```

**④ 后端加 CORS**

前端在 `github.io`、后端在别的地址 —— 跨域，浏览器默认拦截。
项目里已加 `ai-collab-admin/config/CorsConfig.java`。

> ⚠️ 加完要测两件事：
> 1. `OPTIONS` 预检请求被放行（拦截器里有放行逻辑，别删）
> 2. **无 token 访问受保护接口仍被拒绝** —— 确认没把鉴权一起放开

### 8.3 部署步骤（手动推 gh-pages 分支）

比配 GitHub Actions 更稳 —— 产物是本机构建的，百分百可控。

```bash
# 1. 构建
cd ai-collab-hub-web
npm run build

# 2. 用临时 worktree 隔离（不污染 main 分支）
cd ..
git worktree add -B gh-pages /tmp/ghp_deploy
find /tmp/ghp_deploy -mindepth 1 -maxdepth 1 ! -name '.git' -exec rm -rf {} +
cp -r ai-collab-hub-web/dist/* /tmp/ghp_deploy/
touch /tmp/ghp_deploy/.nojekyll      # 关键！见下方说明

# 3. 提交推送
cd /tmp/ghp_deploy
git add -A
git commit -m "部署前端构建产物"
git push origin gh-pages

# 4. 清理
cd -
git worktree remove /tmp/ghp_deploy --force && git worktree prune
```

**然后去 GitHub 设置**：

    Settings → Pages → Source 选「Deploy from a branch」
    → 分支选 gh-pages → 目录选 / (root) → 保存

### 8.4 ⚠️ `.nojekyll` 必须加

产物根目录放一个**空的** `.nojekyll` 文件。

不加的话 GitHub 会用 Jekyll 处理，**下划线开头的目录和文件会被忽略**，
`assets` 里的资源可能 404。

### 8.5 验证部署成功

```bash
# 页面能打开吗（期望 200）
curl -s -o /dev/null -w "%{http_code}\n" "https://shisu0219.github.io/ai-collab-hub/"

# 资源路径对不对（应该带仓库名前缀）
curl -s "https://shisu0219.github.io/ai-collab-hub/" | grep -oE '(src|href)="[^"]*"' | head -4
# 期望 src="/ai-collab-hub/assets/..."
```

### 8.6 常见现象对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 网址 404 | Pages 没部署成功 / 来源选错 | 检查来源是不是「Deploy from a branch」 |
| 页面白屏、控制台一堆 404 | `base` 没配 | vite 加 `base: '/仓库名/'` |
| 刷新页面 404 | 用了 history 路由 | 改 `createWebHashHistory` |
| 页面能开，接口全失败 | **正常** —— 后端没公网地址 | 见第九节，或本机演示 |
| 接口报跨域 | 后端没配 CORS 或拦了 OPTIONS | 检查 CorsConfig + 拦截器 |

## 九、后端公网方案（三选一）

前端上线后，**接口还连不上**（后端在你自己电脑上）。三种解决方式：

| 方案 | 费用 | 稳定性 | 适合 |
| --- | --- | --- | --- |
| **云服务器** | 学生机 ~100/年 | ✅ 长期稳定，有固定域名 | 正式上线 |
| **内网穿透** | 免费 | ⚠️ 地址会变，本机必须开着 | 临时演示 |
| **本机演示** | 0 | 只有现场能用 | **答辩 / 汇报** |

### 9.1 云服务器（推荐长期方案）

    阿里云 / 腾讯云学生机：认证学生后约 9.9/月
    配置 2核2G 足够（Java 后端 + MySQL + Redis 跑一台）

部署流程见第三节（Linux 服务器部署）。

### 9.2 内网穿透（临时）

    cpolar / ngrok / frp 等，把本机 28848 端口映射到公网
    
    限制：
    - 免费版每次重启地址会变
    - 有连接数/时长限制
    - **本机关机就断**

拿到地址后填到 `.env.production` 的 `VITE_API_BASE`，重新构建部署。

### 9.3 答辩演示（本项目当前采用）

**前端线上 + 本地演示** 组合：

    ✅ 前端线上    https://shisu0219.github.io/ai-collab-hub/
                   老师随时能打开看界面
    ✅ 后端本地    本机启动，现场投屏演示完整功能

**如果老师问「为什么线上登录不了」**，标准回答：

> 这是前后端分离项目。前端已部署到 GitHub Pages（免费静态托管），
> 但后端是 Java 服务 + MySQL 数据库，静态托管跑不了，需要独立服务器资源。
> 演示时我在本机启动完整环境。正式上线把后端部署到云服务器、配好域名即可。
