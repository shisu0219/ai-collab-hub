# 08 文件功能对照表

本文逐个说明项目里每个源文件的职责。分三部分：

- 第一部分：后端 `ai-collab-hub-server/`（Java，7 个 Maven 模块）
- 第二部分：前端 `ai-collab-hub-web/`（Vue3，含用户端与管理后台）
- 第三部分：其他文件（SQL、文档、构建配置）

路径约定：`ai-collab-hub-server/ai-collab-admin/src/main/java/com/qll/ucch/` 简写为 `admin/`，
其他模块同理。包名根统一为 `com.qll.ucch`。

---

# 第一部分 后端

## 1.1 模块总览

后端 7 个 Maven 模块，依赖方向单向，不循环：

```
common → integration → notice → blog → admin
                      ↘ security ↗
```

| 模块 | 职责 |
| --- | --- |
| `ai-collab-common` | 公共基础：统一返回体、分页对象、基础实体、异常、常量、枚举 |
| `ai-collab-integration` | 外部集成：文件上传下载、文件类型校验、登录上下文 |
| `ai-collab-security` | 认证鉴权：JWT 工具、登录拦截器、免登录注解、密码编码器 |
| `ai-collab-sys` | 系统与用户域：账号、角色、权限、审核、操作日志、邮件配置 |
| `ai-collab-notice` | 通知域：消息盒子、站内会话与聊天消息、**临时沟通房间**（最新一轮新增） |
| `ai-collab-blog` | 业务核心域：内容填写、字典、对接申请、收藏、**项目小组、答辩意见** |
| `ai-collab-admin` | 启动模块 + 全部 HTTP 接口层（Controller）+ 全局配置/切面 |

> 关键约定：**接口（Controller）全部写在 admin 模块**，业务逻辑在各自业务模块。
> admin 是天然聚合层，跨模块取数（比如显示用户昵称）都在这一层补，不要往 blog / notice 里塞依赖。

## 1.3.1 全局异常处理（admin/handler）

| 文件 | 功能 |
| --- | --- |
| `GlobalExceptionHandler.java` | **全项目异常兜底**，把抛出的异常统一转成 `Result` 返回。已接住：`exception.BusinessException`、**`models.common.BusinessException`（blog 模块那个，必须单独接）**、`UnauthorizedException`、参数校验异常、上传超限、以及兜底 `Exception`。⚠️ **加新异常类型时记得在这里加 `@ExceptionHandler`** —— 漏了就会掉进兜底分支，用户只看到「服务器开小差了」，看不到真正原因（本轮踩过，整个 blog 模块的业务提示都被吞了） |

# 第二部分 前端

## 2.1 前端结构说明

前端是**一个 Vue3 工程**，里面有两条业务线：

- **用户端**（学生 / 老师）：路由 `/cooperation/*`，布局 `CooperationLayout.vue`
- **管理后台**（仅管理员）：路由 `/admin/*`，布局 `AdminLayout.vue`

两者共用同一套 api 封装、同一套登录态、同一个后端。区分点只有三个：路由前缀、布局组件、路由守卫判的角色。

另外有一个公共组件目录：`src/components/`

| 文件 | 功能 |
| --- | --- |
| `OpinionList.vue` | **答辩意见列表组件**（新增）。小组页和项目详情页都用它。**它不做可见性判断** —— 后端已裁剪好，`truncated=true` 时显示「加入本小组可查看完整内容」的提示即可 |

## 按症状找文件

| 症状 | 先看哪里 |
| --- | --- |
| 登录成功但页面不动、URL 带 `?redirect=` 打转 | `utils/authSession.js` 的 `getRoleCode()`、`views/auth/Login.vue` 的跳转逻辑；后端 token 在 `LoginVO.tokenInfo.token` |
| 点详情报「XX 不存在」 | `config/JacksonConfig.java`（Long 转字符串有没有生效）、前端 ID 比较有没有 `String()` 包一层 |
| 页面一片空白，但 build 通过 | 对应的 `.vue` 里有没有「用了但没 import」的图标 |
| 列表有数据但某个名字是空白 | 后端 VO 的字段有没有被赋值；申请人是 `BlogRegistrationController.fillApplicantName`、会话对方是 `ChatController` |
| 角色名显示成「学生」 | `utils/roleDisplay.js` 的 `resolveRoleName()`；页面里有没有残留按角色写死的三元表达式 |
| `utils/unreadBus.js` | **全局未读信号**（本轮新增）。一个 `reactive` 的版本号 + `refreshUnread()` 广播。任何已读操作完成后调一下，顶部导航 `watch` 到就立刻重拉两个红点 —— 不用等 60 秒轮询。**没装 mitt**：需求就是一个计数器加一次广播，Vue 自带的 `reactive` 够用 |
| 「通过/拒绝」按钮不显示 | yaml 的 `default-property-inclusion: non_null` 把 `pass: null` 吞了，前端要写 `row.pass == null` |
| 组外看不到答辩意见 | `BlogOpinionServiceImpl` 的 `resolveScope` / `convert`；先确认小组 `opinion_scope` 和单条 `scope_override` 各是什么值 |
| 「恢复跟随全局」点了没反应 | **MyBatis-Plus `updateById` 把 null 吞了**，必须用 `UpdateWrapper` 显式 set（详见 `11-…记录` 6.6 节） |
| 答辩意见正文显示一半 | 这是摘要档的正常表现，`truncated=true`；组外人员看不到完整内容 |
| 一个小组绑不上第二个项目 | 正常，库里有 `uk_group_article` 唯一索引卡死，一个小组只能有一个项目 |
| 组长邀请成员搜不到人 | `UserFindController` 只放行 `audit_status=1` 且 `enable=1` 的账号 |
| 申请表单下拉框是空的 | `ApplyMetaController`（年级/班级/技能硬编码在那）；或该接口被误加了登录校验，它应该是 `@IgnoreAuth` |
| 临时通道链接打不开、报「登录已失效」 | `TmpRoomController.enter` / `.messages` 必须带 `@IgnoreAuth`（它们是设计成免登录的） |
| 临时通道提示已过期但明明没过期 | 查 `tmp_room.status` —— **判断可用是 `status` + `expire_time` 两个条件**，只看一个会漏 |
| 申请提交了但列表里没年级班级 | `RadioRegistrationServiceImpl.toVO` 里漏了 `setGrade`/`setClassName`/`setSkills`（数据在库里，只是接口没往外给） |
| 列表上看不出哪条是老师发的 | `ArticleListVO.publisherRoleCode` + `BlogArticleController.fillListPublishers()` |
| 管理端角色分布里某个角色是 0 | `SysStatController` 的 `ROLE_*` 常量和 `countUserByRole()` 调用里没加它 |
| 接口报错但前端只显示「服务器开小差了」 | 抛的异常没被 `GlobalExceptionHandler` 接住 → 掉进兜底分支。**查两个同名 `BusinessException`**：blog 模块抛的是 `models.common` 那个 |
| 消息中心和站内沟通的红点不同步 | 两个红点数**两张表**：`notice_box_info.read_status` / `chat_message.read_status`。联动靠 `notice_box_info.ref_id` |
| 找回密码一直失败（提示服务器开小差） | 前端 `ForgotPassword.vue` 提交的字段名是 `password`，后端 `ResetPasswordDTO` 要的是 **`newPassword`** |
| 想同时支持手机号和邮箱找回 | 两种并行：后端两个接口（`/find/pwd/phone`、`/find/pwd/email`）+ 两个 DTO；前端 `ForgotPassword.vue` 用 `mode` 切换，`rules1` 必须是 `computed`（不然后校验空字段会一直报「请输入」） |
| 找回密码要改成手机号 | 后端加 `ResetByPhoneDTO` + `/user/find/pwd/phone`；前端换 `findPasswordByPhone`。**手机号必须同时改成注册必填**，否则没填的人找不回 |
| 读完聊天但消息中心红点还在 | ① `ChatServiceImpl.markSessionRead` 里没调 `markReadByRef`；② 老数据 `ref_id` 是 NULL（加字段之前产生的通知） |
| 操作完红点要等一分钟才变 | 前端 `refreshUnread()` 没被调用；或 `CooperationLayout` 没 `watch(unreadBus.version)` |
| 启动报循环依赖 | `NoticeServiceImpl` 注入了 `IChatService`。改成注入 `ChatMessageMapper` |
| 自己发的消息头像跑到了左边 | 别用 `flex-direction: row-reverse`（会把整行反转），用 `justify-content: flex-end` |
| 老师提交申请提示「请填写你的年级和班级」 | `submitRegistration` 的校验没按角色分；老师的表单不填年级班级，不该用学生那套校验 |
| 老师申请在「我收到的」里显示两个「未填」 | 前端 `isTeacherApply` 判断失效（老师申请的特征是 grade/className/skillList 三者全空） |
| 表单某字段改选填了但保存报 500 | **必填有三层**：前端 `rules` → 后端 DTO 注解 → 数据库列 `NOT NULL`。本轮 email 就漏了数据库那层 |
| 答辩意见的「单独设置」看不到 | ① `OpinionList.vue` 的按钮是 `v-if="isLeader"`，得是组长；② 父页面要传 `:is-leader` 和 `:default-scope` |
| 答辩意见返回体找不到 `scopeOverride` | 它值为 null 时 Jackson `NON_NULL` 不输出这个键 —— **不是 bug**，先设个值再看 |
| 老师点不到「感兴趣」 | 查 `canApply`：列表页和详情页**两处**都有，老规则是「学生只能申请需求、企业只能申请项目、老师 return false」 |
| 文档/页面里还有「企业」残留 | 企业端已彻底删除：11 个企业专属文件删了、`sys_enterprise_info` 表删了、`sys_role` 的 3 号角色删了。见到残留就是漏清理 |
