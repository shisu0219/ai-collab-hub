## 五、开发过程中发现并修掉的问题

| 问题 | 处理 |
|---|---|
| notice 模块包名与其他模块不一致，导致跨模块 import 不到 | 迁移 18 个文件，统一包名 |
| `SecurityContext` 缺 setUserId 等方法 | 补齐，与拦截器调用对齐 |
| 模块用 `IllegalArgumentException` 抛业务错误，全局异常处理器不认 | 换成 `BusinessException` |
| `SysBizException` 独立继承 RuntimeException，处理器抓不到 | 改为继承 `BusinessException` |
| 前端用了 element-plus 不存在的图标 | 换成实际存在的图标 |
| 数据看板 5 个接口后端没实现 | 新建 `SysStatController` 实现 |
| 操作日志接口后端没实现 | 新建 PO + Mapper + Service + Controller + AOP 切面 |
| 拒绝理由模板字段对不上 | 前后端对齐 |
| **两个同名 `BusinessException`**：blog 模块抛的那个全局处理器不认 | 处理器同时接住两个类。**影响整个 blog 模块的业务提示**（之前全被吞成「服务器开小差了」） |
| **MyBatis-Plus `updateById` 的 null 字段不进 SQL** | 「恢复跟随全局设置」功能从未生效，改用 `LambdaUpdateWrapper` 显式 `.set()` |
| **表单必填写三层**：前端 rules + DTO 注解 + 数据库 NOT NULL | 邮箱改选填时漏了数据库层，注册直接 500。三层都要改 |
| **找回密码字段名写错**：前端传 `password`，后端要 `newPassword` | 该功能从未成功过，已修 |
| **数据看板角色分布缺老师** | 后端加 teacherCount，前端改三档 |
| **接口路径凭记忆写错**（测试脚本） | 断言前先从 Controller 抓真实路径 |

> 详细根因和排查过程见 `11-小组与答辩意见改造记录.md`。
